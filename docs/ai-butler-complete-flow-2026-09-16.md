# AI 管家完整流程升级

实施日期：2026-09-16 至 2026-09-20。

本轮把资料读取、业务准备、具体确认、提交、回执核验、成果保存和中断接续放进同一事项。已通过真实后端、真实 Electron 和自建网页的完整流程验收。默认验收使用固定规划器；本轮真实模型验收因临时服务不可达而未完成。

## 实际执行结果

两个流程均读取两份 UTF-8 JSON，绑定并合并字段，在原 Electron 标签页完成一次 HTTP POST，逐项核验引用、日期、中文正文、确认状态及非空回执编号，最后保存实际观察到的 JSON。第一轮规划故意只观察页面，然后结束；后续规划重新创建后端浏览器缓存，验证无需用户输入“继续”也能接续。

| 正常流程 | 6.28 秒 | 2 | 1 | 0 | 1 | 0 / 0 | 回执和文件全部匹配 |
| 回执延迟 | 9.23 秒 | 3 | 1 | 0 | 1 | 0 / 0 | 首次等待超时，自动接续成功 |

两条流程均只打开一次原页面，保留同一标签页；原始资料未改动。确认由验收驱动使用临时原生确认密钥，通过真实审批挑战及执行接口完成；并非人工点击桌面确认框的验收。固定规划器场景模型调用量和模型 token 均为 0。

浏览器独立验收另通过 15 项检查，包括：中文多行读回、原页移交、错误所有者拒绝、隐藏金额篡改拦截、字段别名冲突、输入无效时恢复原值、标准 POST 约束、发送阶段篡改拦截、同一登录资料下的标签页隔离、原生控件编码、实际提交与回执、授权撤销及资料清理。服务端证实篡改请求未到达；拦截后重新确认的正常请求可以成功提交。

## 工程改动

- `file.read_json` / `workflow.merge_data` / `file.write_json` 形成结构化数据链路。重复 JSON 键或冲突来源会失败，避免默默覆盖；写入沿用文件工具的授权、执行前状态、备份和撤销能力。
- `browser_continuity` 从已授权事项恢复原标签页。接续动作和原所有者都进入签名指令，桌面端核对账户、来源和用户接管状态。
- 原页只读回执不再因上游网页内容而要求重复确认。读取固定到已持有标签页，原页消失时失败，不静默打开新网页；网页数据的来源标记继续保留。
- Electron 等待选择器时也限制被页面加载延迟的脚本读取，确保超时真实生效。已确认提交后的等待失败不会触发对整个业务流程的盲目回滚。
- 原生表单合并提交使用浏览器原生赋值及提交，不触发应用输入与提交处理器。金额、隐藏状态和目标仍参与完整快照绑定；原生校验失败则恢复赋值前状态。
- 新增 `browserSubmissionGuard`，把实际 UTF-8 URL 编码 POST 与批准的完整正文逐字节比较，单次批准只放行一次写入。未知或超时的请求不再放行；关闭或撤销会话时先阻止排队请求，再清理资源。隐藏防伪令牌只在 Electron 内部参与比较，不发送给模型或审批界面；比较完成后清除正文缓冲区。
- 同一 Electron Session 的网络监听按 `webContentsId` 路由，打开同一资料下的新标签页不会覆盖原标签页的核验器。被拦截的导航先完成错误收尾，再允许恢复导航，避免旧错误误伤下一次打开页面。
- 修复桌面 WebSocket 认证成功后立即断开的协议协商问题：服务端只回选客户端已提供且认证通过的子协议。
- 修复自动授权交接时的误提醒：执行器刚写入等待阶段、但尚未释放运行记录时，协调器等待检查点保存，不把目录授权内的可逆写入显示成用户决策。编辑、归档和 JSON 保存均覆盖原执行器及重建执行器的交接测试。
- 仅参数契约完整的浏览器工具启用确定性执行，避免错误宣称可跳过模型调用。
- 撤销入口检查完整执行账本。包含不可回滚提交、未知执行或人工恢复项的事项不会标记为可整体撤销；单独的 JSON 文件修改已通过真实审批、写入、重建执行器和撤销测试。

## 复现

在 Windows 工作区激活项目虚拟环境，确保已安装桌面依赖：

```powershell
$env:PATH = "$PWD\.venv\Scripts;$env:PATH"
npm --prefix desktop run build:electron:dev
npm run eval:butler:flow
npm run eval:butler:flow -- --scenario receipt_delay --report .tmp/audit-fixes/butler-complete-flow-delay.json
npm run eval:butler
```

模型服务恢复后可执行：

```powershell
npm run eval:butler:flow -- --real-model --prompt-key --base-url http://localhost:56622/v1 --model gpt-6-astra
```

密钥仅在无回显提示中输入并保留于本次进程；不修改用户保存的模型配置。原生测试使用自己的隐藏窗口、临时资料与本地测试网站；退出时关闭这些窗口并清理浏览器资料。

## 当前边界

一次确认的合并提交目前适用于有明确 action、同窗口、UTF-8 `application/x-www-form-urlencoded` 编码和普通字段的原生 HTML POST 表单。文件上传、其他编码及依赖页面脚本计算的表单不走该合并路径；请求守卫不允许把批准的原生提交改成脚本或 iframe 写入。普通点击、其他交互式页面及第三方支付、认证与验证码仍需分阶段准备或用户接管，不能据此宣称任意订票网站均可一次完成。

执行结果未知时，网页回执检查可提供核对证据，但不会伪造原提交日志的成功状态。跨事项或所有权改变的网页不自动接管；完整业务已对外提交的事项也不会宣称可整体撤销。本轮验证的是这套完整执行链路；真实模型在第三方站点上的成功率仍需单独验收。
