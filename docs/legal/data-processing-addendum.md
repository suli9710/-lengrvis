# 数据处理协议（Data Processing Addendum, DPA）

**版本**：v0.1（草稿）  
**生效日期**：随企业/Team 商业许可签署生效  
**状态**：草稿，法务定稿前不得对外签署

---

本 DPA 是 EULA / 商业许可协议的附件，适用于许可方代表客户处理个人数据的场景。当本 DPA 与主协议冲突时，就数据保护事项以本 DPA 为准。

## 1. 角色界定

- **客户（控制者 / Controller）**：决定个人数据处理目的与方式的一方（通常为采购 Team/企业许可的组织）。
- **许可方（处理者 / Processor）**：cow milk，仅按客户的合法指示处理个人数据。
- **重要边界**：Lengrvis 为**本机优先**软件。用户的任务正文、文件索引、对话、审计链等默认存储于用户本机 SQLite，**不经过许可方的任何服务器**。在默认本机模式下，许可方实际上**不接触**这些个人数据，因此就该部分数据许可方既非控制者亦非处理者。本 DPA 仅在许可方确有处理客户个人数据的环节（如未来的云端账户、托管遥测、支持工单）适用。

## 2. 处理范围

| 项目 | 说明 |
| --- | --- |
| 处理对象 | 仅限客户通过受许可方控制的渠道（支持工单、可选托管遥测、账户系统）提供的个人数据 |
| 明确排除 | 用户本机存储的任务/对话/文件/审计数据（不离开本机，许可方不可访问） |
| 处理目的 | 提供与维护软件、技术支持、按客户指示的特定处理 |
| 数据主体类别 | 客户的授权用户/员工 |
| 数据类别 | 账户标识、联系方式、支持沟通内容、（启用时）匿名遥测 |
| 处理期限 | 至主协议终止或客户要求删除为止 |

## 3. 处理者义务

1. 仅按客户书面合法指示处理；指示违法时及时告知。
2. 对获授权处理人员实施保密义务。
3. 采取与风险相称的技术与组织措施（见 `docs/compliance/security-whitepaper.md`）。
4. 未经客户事先书面授权不启用新的子处理方；现有子处理方见 `docs/legal/subprocessors.md`，变更将提前通知并给予异议期。
5. 在法律允许范围内，协助客户响应数据主体权利请求（访问、更正、删除、可携、拒绝）。
6. 协助客户完成 PIA/DPIA 与监管沟通。
7. 协议终止后，按客户选择删除或返还个人数据（法律要求保留者除外）。

## 4. 数据泄露通知

- 许可方在确认涉及客户个人数据的安全事件后，**不晚于 72 小时**通知客户。
- 通知内容包含：事件性质、涉及的数据类别与大致规模、可能后果、已采取与拟采取的缓解措施、联系人。
- 通知渠道：客户预留的联系邮箱与商业许可指定联系人。

## 5. 跨境传输

- 默认本机模式无跨境传输。
- 若客户选择云端 LLM provider，由客户自行配置并与该 provider 直接构成处理关系；许可方不中转该数据。
- 涉及向第三国传输个人数据时，依据适用法采用标准合同条款（SCC）或等效机制，并完成必要的传输影响评估（PIPL 出境路径另行评估）。

## 6. 审计

- 客户可每 12 个月一次、提前 30 日书面申请，对本 DPA 履行情况进行审计；许可方可提供第三方审计报告（见认证路线）替代现场审计。

## 7. 子处理方

现行子处理方及其用途见 `docs/legal/subprocessors.md`。新增/替换将提前通知，客户可在合理期限内提出异议。
